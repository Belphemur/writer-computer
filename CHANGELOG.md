# Changelog

## Unreleased

- Agent: archiving a project now moves its folder (notes, `AGENTS.md`, chats and memory) into `Archive/Projects` (setting "Archived projects folder", Settings > Agent) and hides it from the project switcher, new-chat choice and the sidebar badge; a name that is already taken gets " 2", " 3". It is refused while a chat of the project is working or waiting for a permission, and idle chats of it are stopped first. The project browser has a collapsed "Archived" section with Unarchive, which moves the folder back to where it came from so its chats resume; a "…" menu on the project home and on each switcher row (also right click) has "Change icon…" and "Archive project…", the palette has "Agent: Archive project" and "Agent: Unarchive project...", and the CLI has `writer project:archive path=<folder>` and `project:unarchive path=<folder>`. Links that include the folder path (`[[Projects/X/Note]]`) are not rewritten. Tested in Rust (move, clashes, rollback, restore targets, busy guard with a fake `claude`, CLI round trip) and jsdom.
- Links: `[[Note#Heading]]` and `[[#Heading]]` now jump to the heading (before, the note opened and the heading was ignored), in the editor, properties, the agent pane, Bases and Obsidian plugin-rendered links (`openLinkText("Note#Heading")`). It follows the click rule: the same tab, or a new tab that scrolls when it is shown (`Cmd`/`Ctrl`+click opens it in the background); `[[#Heading]]` scrolls the note you are in. The match ignores case and punctuation, `[[Note#A#B]]` goes to `B`, a missing heading opens the note at its top silently (Markdown `#slug` links keep the "heading not found" notice), and `#^block` links open the note without scrolling to the block (not supported yet). Tested in jsdom; not seen in a real window. Spec: [`SPECs/link-activation-spec.md`](SPECs/link-activation-spec.md) "Heading fragments".
- Agent: a project without a color keeps the muted grey badge on its folder in the sidebar; it had turned accent-colored when project colors arrived (the icon elsewhere still uses the accent). Tested in jsdom.
- Agent: a link to a base view in an agent reply (`[[Tasks.base#Board]]`) now opens the base on that view, as it does in the editor; it dropped the view before. Links in the agent pane, the editor, properties and Bases now open through one shared path.
- Agent: pasted, dropped and picked images in the chat now show their thumbnail in the composer chip and the sent message, and a click opens the image tab (before, they showed an icon and "Can't show this image": the images are saved in a hidden `.writer/chats/assets` folder that the app's image access did not serve; exactly the chat image folders are now allowed, nothing else in a hidden folder).
- Tables: links and formatting in the fullscreen table now work. Inline code, links and the other styles of a cell were drawn unstyled there (the editor's theme did not reach the overlay; it now carries the editor's own theme scope). Wiki links, Markdown links and bare URLs in a cell were drawn as plain text and did nothing; they now look like links in the note and open the same way (click, middle click, Cmd/Ctrl+click; URLs in your browser). A note opened in this tab closes the fullscreen view first, a background tab (middle or Cmd/Ctrl+click) and URLs leave it open, and clicking elsewhere in the cell still edits it. Tested in jsdom; not seen in a real window. Spec: [`SPECs/table-editing-spec.md`](SPECs/table-editing-spec.md).
- Agent: sub-agent work now gets its own card instead of mixing into the main timeline. Each delegated run (Explorer or Worker) shows its role with an icon, the model it runs (resolved from your tier settings by Writer, not guessed), its task, status (running, waiting for permission, done, failed, stopped), elapsed time and counts (tool calls, files read, edits); its own tool rows, thinking and text are inside, open while it runs and collapsed when done, its final answer is the summary, parallel sub-agents are separate cards and background ones follow their own status. The Changes card's role label jumps to the card that made the edit, a sub-agent's permission card says "Worker wants to edit ...", and reopened chats keep the cards (chats saved before this show the old flat list; a sub-agent's text is no longer mixed into the saved answer). Tested in Rust (mapper, resolved model, goldens) and jsdom; not seen in a real window, and the new parallel fixture is built from the observed line shapes, not a new real capture. Spec: [`SPECs/native-agent-spec.md`](SPECs/native-agent-spec.md) section 3.14.
