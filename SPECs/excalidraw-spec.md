# Excalidraw (built-in feature)

Decision: [ADR 2026-11-18, draw natively with a built-in Excalidraw feature](../docs/decisions/2026-11-18-draw-natively-with-a-built-in-excalidraw-feature-compatible-with-obsidian-drawings.md). Feature folder `apps/desktop/features/excalidraw/`, kill switch `features.excalidraw.enabled` (on by default). Frame and scroll rules: `docs/design.md`.

## What it does

- Opens, edits and saves `*.excalidraw.md` (the Obsidian Excalidraw plugin's shape) and plain `*.excalidraw` (the standard JSON). Obsidian keeps opening what Writer saves.
- "New drawing" (palette, the sidebar's New section) creates a native `Drawing.excalidraw` (plain Excalidraw JSON) and opens it. `excalidraw:create` with a path without a suffix also writes `.excalidraw`; `.excalidraw.md` (the Obsidian plugin's shape) is written only when the path asks for it, and existing `.excalidraw.md` drawings are read and edited in their own format (2026-11-19, the user: "It should be native").
- `![[Arch.excalidraw.md]]` or `![[Arch.excalidraw]]` alone on a line renders the drawing in the note (SVG, cached by content hash); a click opens the tab.
- "Export drawing as SVG" writes `<name>.svg` next to the drawing. Setting `excalidraw.auto-export-svg` (off) keeps it current after every save and every outside change.
- Agents: `writer excalidraw:create|add|update|read|lint|preview|export` and the managed skills `writer-excalidraw` (the commands) and `writer-diagram` (the workflow: research the vault, model, lay out, lint, preview, link; both installed only while the feature is on) (Rust half, works with the app closed except `preview` and `export`). An agent looks at its work with `preview` (a PNG outside the vault) and fixes it with `update`: the skill teaches the loop create or add, preview, update, preview.
- Live reload: a change made outside (agent, CLI, sync) merges into the open canvas; new elements are drawn in (about 300 ms, none with reduced motion).

## Files

- `.excalidraw.md`: front matter and banner untouched; `# Excalidraw Data`, `## Text Elements` (`text ^id`, 8-character ids), `## Element Links` (`id: link`, a blank line after each, written only when an element has a link: the plugin's own section, so Obsidian's graph sees the links; an element that carries a link gets an 8-character id like a text element, `shorten_text_ids` in both codecs), `## Embedded Files` (`id: [[target]]`), then the `%%`-fenced `## Drawing` block, `compressed-json` (lz-string base64, 256-character rows) or `json`. Unknown sections are kept byte for byte, CRLF is kept, an unchanged scene returns the original text.
- Images: in a `.excalidraw.md` a pasted image is saved as a vault attachment and listed under `## Embedded Files`; in a plain `.excalidraw` it stays inline in `files`.
- One write path per language: the TypeScript codec (`web/lib/excalidraw-md.ts`, the editor) and the Rust codec (`rust/excalidraw_md.rs`, the CLI), pinned to each other by `apps/desktop/shared/excalidraw-fixtures/` (sample files, lz-string vectors, `expected.json`). The format knowledge came from reading the Obsidian Excalidraw plugin's source (AGPL-3.0, cloned outside the repo); no code was copied (the `## Element Links` format was read from the same source, 2026-11-19).
- Links in the index: the `link` of a drawing's elements (`[[Note]]`) are links of the drawing file, for `.excalidraw` and `.excalidraw.md` alike, so `graph:backlinks`, the graph view (with attachments on, a drawing is a non-note node) and unresolved links see them. The one seam is the file kind's extractor: `Extracted::links` (`index/kinds.rs`), parsed by the note scanner in `index/build.rs` (`extracted_links`) and written as `edges` rows; a drawing note's own `## Element Links` lines are not counted twice. No special case in the index for drawings.
- Listing: `.excalidraw.md` is a note; plain `.excalidraw` is listed while the excalidraw feature is on (the `drawing` file kind, `index/kinds.rs`; the code-files switch and the extension list do not matter) and opens in the drawing kind, never as text. Drawings are found by the text of their elements in search (`search-spec.md` "File kinds").

## Core and feature

- Core keeps the `drawing` page kind (`src/components/editor-area/page-kinds/drawing.ts`: `feature: "excalidraw"`, `claimsWhenOff`), `isDrawingPath` and `lib/drawing-files.ts`. Switched off, a drawing's tab says it is off (Turn on, Open as text), embeds stay plain links and the CLI commands say so.
- The embed's React block-widget host is shared with Bases: core `src/lib/react-block-widget.ts` (`ReactBlockWidget`, `HeightMemory`); neither feature imports the other.
- The feature owns the view (`page-view:drawing` slot, lazy), the embed editor extension, commands, the disk-sync workspace listener and the `excalidraw:render` window answer (`ipcRequests`, `web/render.ts`: SVG markup or base64 PNG through Excalidraw's `exportToSvg` / `exportToBlob`, one renderer for `export` and `preview`). `web/index.ts` imports only light modules; a test pins that the startup graph and the entry chunk never reach `@excalidraw/excalidraw`.
- Embeds (`![[x.excalidraw]]` alone on a line): a picture (the live SVG, redrawn on a change from outside or a save of Writer's own). A plain click or Enter turns it into the Excalidraw canvas inside the note, at the picture's height (at least 200 px) and the editor's content width, theme following the app; Esc outside a text box, or a press outside the canvas, returns to the picture, redrawn from the saved scene. One inline editor at a time (`web/lib/inline-editor.ts`, named by the widget's host element, so a rebuilt widget is a picture again): opening a second closes the first. Cmd/Ctrl+click and middle click open the tab (`linkHandlers`, `onCurrent` replaces only the plain click). The canvas (`components/drawing-canvas.tsx`, the one host of the tab too) is a lazy chunk fetched on the first click. With the drawings handed to the plugin (`excalidraw.handle-files` = `plugin`) a click opens the tab, as before. The widget ignores events (`ignoreEvent`), so keys and the pointer in the canvas never reach the note's selection, keymap or undo; Zoom chords are not taken by the editor while focus is in a canvas (`no-viewer` is also false there, `data-drawing-canvas`).
- One session per file (`web/lib/sessions.ts`, `acquireDrawingSession`): a tab and any inline editors on a drawing hold one `DrawingSession`, refcounted; the last holder flushes and closes it, and a session being closed is awaited before the next opens. It owns the one save path, the one `track` of the disk store and the reload on a change from outside. The session holds several canvases: an edit in one is merged into the others by id and version (`reconcile`, never an undo step there), a reload animates the first canvas and reaches the others when it settles, and a canvas that joins starts from the unsaved edits.
- Coexistence: setting `excalidraw.handle-files` (`native`, `plugin`) is answered by the `excalidraw.files` service; `plugin` hands the files back to the Obsidian plugin. With the plugin running, the first drawing opened asks once whether to turn the plugin off in Writer's own plugin state (never `.obsidian/`).

## Rust

`rust/`: `lz.rs` (lz-string over UTF-16), `excalidraw_md.rs` (codec), `layout.rs` (layered layout: longest-path layers, barycenter order, new blocks below existing boxes), `elements.rs` (spec to elements: wrapping and sizing, bound text, arrow bindings and routes, groups, `customData.writerId`, `validate_scene`), `elements/spec.rs` (the grammar and its parse, every bad item listed), `elements/zones.rs` (zones as frames, the legend), `elements/read.rs` (`read_spec`, link targets), `lint.rs` (`excalidraw:lint`), `cli.rs`, `elements/update.rs` (`excalidraw:update`), `previews.rs` (the temp folder of previews), `ipc.rs` (the `excalidraw:export` and `excalidraw:preview` socket commands: must-be-open vault, confined path; the window hands the image to Rust, since the socket carries 64 KiB, and the CLI gets one path back: vault-relative for `export`, absolute for `preview`), `mod.rs` (`Feature`, the skill). No `tauri` types outside `mod.rs`/`ipc.rs`.

## The diagram spec (lane 1)

One spec model (`elements.rs`) for `create`, `add`, `update` and what `read` prints, so `read` then `create` reproduces the drawing's spec (pinned by a seeded property test, `rust/tests/diagram.rs`).

- **Input.** `spec=` is JSON, `spec=@<vault file>` (confined: never outside the vault, never `.obsidian`) or `spec=-` (stdin). Resolved once for every JSON-valued parameter in `cli/mod.rs` (the spec's `ParamSpec::json`), not per command, and `-` is refused over MCP (its stdin is the protocol). A JSON value reaches the parser as written: the arg layer no longer unescapes `\n` inside it. See `writer-cli-spec.md`.
- **Wrap.** A text wraps at the box's `w` (the text area of its shape: rectangle `w - 40`, ellipse `(w - 40) / 1.3`, diamond `(w - 40) / 1.7`); without `w` the box grows to fit up to 15.6 em of text, then wraps. A word wider than `w`, or lines taller than `h`, is the error "the text overflows its W x H box, it needs at least ...".
- **`check`** (flag on `create`, `add`, `update`): runs the whole build on a copy and writes nothing. Not JSON or not an object is exit 2; every other problem (unknown field, bad value, unknown id, overflow) is exit 1 listing all of them, `nodes[2] (db): ...` per item. A normal run reports all problems the same way. On success `check` prints `OK: would ...` and, as `note:` lines, the `lint` findings of the result.
- **Nodes:** `id`, `text`, `shape`, `x`, `y`, `w`, `h`, `color` (outline and fill), `fill`, `stroke` (override one half), `fontSize` (6 to 200), `strokeStyle` (`solid`, `dashed`, `dotted`), `link` (`[[Note]]` or a URL, stored in the element's `link`).
- **Edges:** `[from, to]`, `[from, to, label]` or `{from, to, label, style, color, bidirectional, labelAt, fromSide, toSide, route}`. `bidirectional` puts a head at both ends. `labelAt` (0 to 1) cannot be a bound text (Excalidraw centres those), so an off-centre label is a free text with `customData.writerLabelOf` and `labelAt`; `read` and `update` treat both kinds as the arrow's label. Sides and `route: "elbow"`: the arrow runs between the middles of the chosen sides (the facing sides when only a route is given); an elbow is `elbowed` with orthogonal points and `fixedPoint` bindings, and the chosen sides are kept in the arrow's `customData.writerSides`, so a later move redraws it the same way. Excalidraw may route an elbow itself when it loads or when a bound box is dragged; that is its own, valid, path.
- **Zones:** `{id, label, nodes, color, padding}` is an Excalidraw frame (`name` is the label, drawn top-left outside the frame; `strokeColor` is `color`; padding default 40, kept in `customData`) sized around its members, their labels and the arrows between two members, which all carry `frameId`. A box is in one zone and zones do not nest (frames do not in Excalidraw): both are errors. `update`: `zones[]` change label, colour, padding or the member list (a new id with `nodes` creates one), `remove.zones` removes the frame and keeps the boxes; a box moved or grown refits its zone (zones the user drew by hand, with no `writerId`, are never refitted). Automatic layout does not yet keep a zone's boxes together (lane 2): position zone members, or `lint` reports `zone-contains-box`.
- **Legend:** `legend: [lines]`, text under everything already drawn (`customData.writerLegend`, in order, font 16); `add` appends below the last line; `read` lists them and they are not nodes.
- **`excalidraw:lint`** (read-only): JSON `{path, clean, findings:[{kind, ids, message}]}` or lines (`format=text`). Kinds `label-over-label`, `label-over-box`, `arrow-through-box`, `text-overflow`, `zone-contains-box`, from the elements' geometry, so it also judges a drawing a person made. Exit 0 whatever it finds.
- **`excalidraw:read`** prints the spec (nodes with position, size, colours, style, link; arrows with every option; zones; groups; legend; `other` counts, ignored by `create`); `format=json` is `{path, title, links, spec}`.
- **Links in the file:** `## Element Links` (see Files) is written and kept in step by both codecs.

## `update` and `preview`

`excalidraw:update path=... spec=...` edits the file directly like `add` (works with Writer closed), with the same spec types, colours and sizes (`w`, `h`; an arrow may be `{"from","to","label","color"}`) plus `remove`:

- `nodes[]` patch the box named by `id` (the id it was created with, or its element id): `text` (`""` clears), `shape` (rectangle, ellipse, diamond), `color`, `x`+`y` (move: the label goes along and every arrow ending on the box is redrawn straight between its ends, labels back on the middle), `w` and `h` (the text must fit, else an error naming the box). A relabelled or reshaped box grows to fit, never shrinks.
- `edges[]` address an arrow by `[from, to]` (all arrows from `from` to `to`) and set a label (`""` clears) and/or a colour; they never create an arrow (use `add`).
- `remove.nodes` deletes boxes with their label and every arrow on them and those labels; `remove.edges` deletes arrows `[from, to]`. Boxes that lost an arrow move on (version), so an open tab reloads exactly what changed (the reconcile rule already drops what a file no longer has and takes the higher version).
- An unknown id, arrow or colour is exit 1 naming it, and the whole update is checked on a copy so nothing is written. `direction`, `groups` are refused; `remove` is refused by `create` and `add`. Elements not named, freehand, images and the file's sections stay byte for byte, in both encodings.

`excalidraw:preview path=... [format=png|svg] [scale=0.5..4]` asks the running app (exit 4 `Writer is not running` otherwise) to render the drawing and prints the absolute path of the image, in `writer-previews/` under the OS temp dir (`0700`, files `0600`, never in the vault, files older than an hour swept by the next preview). Default `png`, scale 1. `excalidraw:export` shares the renderer and the socket path and writes `<name>.svg` (default) or `<name>.png` beside the drawing in the vault. Neither logs a path or contents.

## Network, fonts

No request: `window.EXCALIDRAW_ASSET_PATH` is `/excalidraw-assets/`, served in dev and emitted on build by `features/excalidraw/vite-assets.ts` from the package. The Xiaolai CJK font (12 MB) is left out; CJK text falls back to the system font. The CSP is unchanged.

## Live reload

`DrawingSession` (`web/lib/session.ts`) owns the debounced save (600 ms), the reload and ignoring `onChange` during the draw-in. `reconcile` (`web/lib/reconcile.ts`) merges by id and version with Excalidraw's rule (local wins when its version is higher, or equal with the higher `versionNonce`); a map of base versions tells an outside deletion from an unsaved local addition. The merge is applied as elements only with `captureUpdate: NEVER`, so zoom, scroll and undo stay.
