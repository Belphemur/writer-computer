## 4. Recommendation

Keep our mapper for now; track `claude-codes` and use it as a drift oracle. If the user wants fewer hand-maintained shapes, adopt partially (types for stdout, `types` feature only, `default-features=false`).

Reasoning:

- It does track the CLI closely (crate version == tested CLI version, ~1 day lag, automated binary-schema drift check). That matches the user's claim; it is the one community crate worth using.
- But the parts that matter most to us are not covered or are brittle: stream_event inner events are raw `Value`; no `set_permission_mode`; unknown control subtypes and unknown top-level types hard-fail (we need request_id to reply with an error); `decision_reason` typed as `String`; fields we use (`display_name`, `description`) are dropped. We would keep a Value-first pre-pass and our own delta mapper, leaving little to replace. Our mapper is ~1400 lines already tested against goldens and already tolerant.
- Single maintainer, new dep (chrono added), and our policy requires telling the user before adding a dependency.

Migration sketch (only if approved):

1. Add `claude-codes = { version = "=2.1.325", default-features = false, features = ["types"] }` (exact pin; bump deliberately with CLI bumps).
2. In `claude_stream.rs`, parse each line to `serde_json::Value` first; read `type`/`request.subtype`; try `ClaudeOutput` for known types, fall back to Value on Err (never drop the line, always answer unknown control_requests with an error `control_response`).
3. Map `InitMessage`, `ResultMessage`, `ToolPermissionRequest` into `events.rs` types; keep our own stream_event delta code and stdin encoders (set_permission_mode via raw JSON).
4. Run fixtures + goldens unchanged to prove parity; keep `events.rs` as is.
   Risks: single-maintainer supply chain (pin exact, vendor-review diffs on each bump, check cargo-vet/audit status: no cargo-vet/audit/deny tools installed locally, none checked); crate may lag/skip CLI versions (2.1.326 currently has no crate); fields dropped silently by typed structs; Apache-2.0 attribution.

Cheaper alternative the user may like: do not depend on it, but use its `tests/schemas/claude_stream_json_snapshot.txt` and CHANGELOG as a free changelog of wire changes per CLI release when we bump our own supported version.
