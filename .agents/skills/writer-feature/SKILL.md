# Writer built-in features

Read `.agents/skills/engineering-philosophy/SKILL.md` first (DRY > SOLID > KISS) and `docs/consolidation.md`. Design: `SPECs/builtin-plugins-spec.md` (the contribution-points table is section 6.5; sections 2, 5, 15-18 are cited below). Do not restate the spec here: link to it in code comments and docs.

## 1. Feature or core?

A **feature** is first-party code that adds to core through declared contribution points and can be switched off (`features.<id>.enabled`) to save memory or contain a crash. Make it a feature when it is optional, self-contained and core can work without it (agent pane, tables, a future status widget).

It stays **core** when others depend on it for the app to work: editor, tabs, sidebar tree, workspace, settings engine, index, watcher, logging, the Obsidian host shim. Core never imports a feature (import-graph tests check it, e.g. for tables); features depend on core and use only `@/lib/features/*` registries. If a feature needs something core lacks, add a contribution point (section 7), never an `if (feature)` branch in core.

Reference examples: `apps/desktop/features/tables/` (TypeScript only: no `rust/`, no capability file) and `apps/desktop/features/agent/` (full: Rust plugin, hooks, settings fragment, dock, settings page, bindings).

## 2. Layout

```
apps/desktop/features/<id>/          <id>: kebab-case = folder = plugin name = prefix of everything it owns
  feature.json                       manifest (section 3)
  settings.schema.json               optional settings fragment (keys start with "<id>.")
  web/index.ts                       export default defineFeature({...}); import-light
  web/ipc.ts                         typed client of the Rust commands (only if it has Rust)
  web/bindings.ts                    GENERATED by tauri-specta, never edited, imported only by ipc.ts
  rust/mod.rs  rust/bindings.rs  rust/commands/   (only if it has Rust)
  tests/                             `vp test` picks up features/*/tests
apps/desktop/src-tauri/capabilities/features/<id>.json   (only if it has Rust commands)
```

TS-only feature: `feature.json`, `web/index.ts`, `tests/`. That is zero shared-file edits (the loader globs `features/*/web/index.ts`).

## 3. Manifest `feature.json` (spec section 2; only what exists today)

Required: `id`, `name`, `version`, `description`, `enabledByDefault`, `memory: { level: low|medium|high, note }`, `activation` (`onStartup` | `onWorkspaceOpen` | `onFileKind:<k>` | `onView:<id>` | `onCommand:<id>`; only `onStartup` is acted on by the loader, the rest are lazy by use).

`rust`: `commands` (must equal the `#[tauri::command]` fns, contract test), `events` (`<id>:<name>`, never a dot), `hooks` (`setup`, `onWorkspaceOpen`, `onWorkspaceClose`, `onExit`), `skills`, `cliCommands`, `indexDdl`.

`contributes` (every contributed id starts with `<id>.`):

| Key               | Shape                                                   | Registered in `defineFeature` as                                                                                               |
| ----------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `commands`        | `[{ id, label, description, when }]`                    | `commands: [{ id, label, when, run(ctx, feature) }]`                                                                           |
| `keybindings`     | `[{ id, keys, description }]`                           | `keybindings: [{ ..., run(feature, e) }]`                                                                                      |
| `docks`           | `[ids]`                                                 | `docks: [{ id, priority, isOpen, width, close, subscribe, load }]`                                                             |
| `sidebarPanels`   | `[ids]`                                                 | `sidebarPanels: [{ id, label, icon, order, load }]`                                                                            |
| `sidebarActions`  | `[ids]`                                                 | `sidebarActions: [{ id, label, icon, order, run(feature) }]`                                                                   |
| `statusItems`     | `[ids]`                                                 | `statusItems: [{ id, order, load }]` (component gets `{ filePath }`)                                                           |
| `menus`           | `{ "<surface>": [ids] }`                                | `menus: { "<surface>": [{ id, items(...target) }] }`; surfaces `editor-body`, `sidebar-file`, `sidebar-folder`, `sidebar-bulk` |
| `settingsSection` | none (a page)                                           | `settingsSection: { id, label, order, load }`                                                                                  |
| `secrets`         | `[{ key: "features.<id>.<name>", label, description }]` | `ctx.secrets.get/set/delete(key)`                                                                                              |
| editor extensions | none                                                    | `editorExtensions: [{ id, when?, load }]`                                                                                      |

Icons come from `@hugeicons/core-free-icons`. `load` thunks are dynamic imports. `web/index.ts` imports only `defineFeature`, the manifest JSON, tiny state modules and `import()` thunks: it is loaded eagerly at startup, so a heavy import there lands in the startup chunk.

## 4. Steps: new TypeScript-only feature

1. Search for an existing contribution point that fits (spec 6.5). No fit: add the point as a registry in `src/lib/features/` plus one `removeOwner` and one `add` loop in `registry.ts`, one row in the spec table, a fixture test (see `tests/features-sidebar-contributions.test.tsx`).
2. Create `feature.json` and `web/index.ts` (`manifest.contributes` ids = definition ids: `tests/features-contract.test.ts` fails otherwise).
3. Add the kill switch to `apps/desktop/shared/settings.schema.json` verbatim as the Rust contract test prints it (`features.<id>.enabled`, category "Features"). Its description has no restart sentence for a TS-only feature.
4. Settings of its own: `settings.schema.json` fragment (every entry: key with `<id>.` prefix, label, description, category, type, default). The Settings sidebar shows a generated page; give it a custom one with `settingsSection` if rows are not enough.
5. Tests in `features/<id>/tests/`: registers and unregisters cleanly (counts return to zero), kill switch removes everything, a throwing contribution is contained, core has no import of the feature.
6. Docs (section 8), then validation (section 9).

## 5. Steps: add a Rust half (what `agent` does)

1. `rust/mod.rs`: `pub struct X; impl<R: Runtime> Feature<R> for X` with `manifest_source` (`include_str!("../feature.json")`), and only the hooks needed. `settings_source` for a fragment, `invoke_handler` for commands, `on_workspace_close` / `on_exit` to stop what it started. Pure logic goes in a Tauri-free module (`rust/core.rs` or an existing core module); command handlers stay thin.
2. Mount it with one `#[path = "../../../features/<id>/rust/mod.rs"] mod <id>;` and one entry in `registry()` in `src-tauri/src/features/mod.rs`. Those are the only shared Rust edits.
3. Commands: `async`, generic over the runtime, `#[tauri::command]` + `#[specta::specta]`, disk or lock work through `commands::blocking`. List them once in `rust/bindings.rs` (`collect_commands!`, `plugin_name("<id>")`, the bindings diff test). Generate the TS: `WRITER_UPDATE_BINDINGS=1 cargo test bindings`, commit `web/bindings.ts`. The plain test fails when it is stale.
4. `web/ipc.ts` is the only importer of `bindings.ts` (types only) and the only caller of `featureInvoke("<id>")` (route `plugin:<id>|<cmd>`, manifest guard). The rest of the web half calls ipc.ts wrappers, never `invoke` and never the generated runtime. Events: `featureEvents` / `ctx.listen` (`<id>:<name>`).
5. Capability file `src-tauri/capabilities/features/<id>.json`: identifier `feature-<id>`, windows exactly `["main", "w-*"]`, permissions `["<id>:default"]`. `build.rs` makes the `<id>:allow-<cmd>` permissions from `rust.commands`; no other build code.
6. Contract tests (`features/contract_tests.rs`) cover manifest vs commands vs capability vs settings vs contribution ids; add Rust tests for hooks and for the commands under the real ACL (see `features::agent::tests`).
7. No new dependency without an explicit go from the lead.

## 6. Settings and secrets

Settings: a fragment in `features/<id>/settings.schema.json` is merged into the schema on both sides (`config::load_schema`, `lib/settings-schema.ts`); never copy keys into `shared/settings.schema.json` (only the kill switch lives there). Replace hand counts in tests with the fragment contract.

Secrets: declare in `contributes.secrets`; read and write only through `ctx.secrets` (web) or `features::secrets::{secret, set_secret, delete_secret}` (Rust, call through `commands::blocking`). One Keychain item, scope rule enforced once in `features/secrets.rs` (a feature reaches only keys its own manifest declares). Never put a secret in a setting, a log line, an event or a bindings snapshot; `SecretValue` has no `Display`/`Serialize`. Spec section 17.

## 7. Crash containment (spec section 16): non-negotiable

- Everything that runs feature code at a boundary goes through `features::guard`; commands are wrapped once by the runner (`contain`; a failed feature answers `AppError::FeatureUnavailable`); threads start with `features::spawn(app, id, name, f)`; never `std::thread::spawn` raw.
- Native code that stays live (event monitors, observers) is installed through `features::native(app, id, setting, f)` so a crash turns exactly that setting off next launch. Prefer DOM or webview APIs over native hooks.
- `setup` registers cheap state only: no threads, watchers, processes or SQLite handles. Start them in `on_workspace_open` or on first command, only while enabled.
- Web: contributed UI renders through `FeaturePane` (inside `FeatureBoundary`); failures are reported through the health store (`recordFailure` / `reportOwnerFailure`), never swallowed. Three failures switch the feature off for the session.
- Fail explicitly and log with `logger` / `log::` (never note contents, vault paths or secrets; never `console.log` / `eprintln!`).

## 8. Kill switch and docs

`features.<id>.enabled` (global scope, default `enabledByDefault`). Off: the web half unregisters at once (every contribution removed); the Rust half is never set up or added as a plugin until restart. A new TS state must reset on deactivate.

Update in the same change: the spec (`SPECs/builtin-plugins-spec.md` section 15/6.5, or the feature's own spec in `SPECs/`), `CHANGELOG.md` (one user-visible line, name the feature), `TODOS.md` (item names the feature id), the `features/` line of `CLAUDE.md` when a new kind of thing lands, and `docs/keyboard-shortcuts.md` for a keybinding (a test ties it to the registry). A decision that is hard to reverse needs an ADR (`adr-skill`).

## 9. Validation

From `apps/desktop`: `pnpm exec vp check` and `pnpm exec vp test`. With Rust, from `apps/desktop/src-tauri`: `cargo test && cargo fmt --check && cargo clippy` (and `WRITER_UPDATE_BINDINGS=1 cargo test bindings` once if commands changed). A timing-flaky test that passes on rerun is not yours; name it.

## 10. Checklist

- [ ] Feature, not core; no core import of the feature; no per-feature branch in core.
- [ ] Folder layout; id kebab-case; every contributed id prefixed `<id>.`.
- [ ] `feature.json` complete (`memory`, `activation`, id lists equal the definition).
- [ ] `web/index.ts` import-light; heavy parts behind `load`.
- [ ] Kill switch in the shared schema verbatim; settings in a fragment; secrets declared.
- [ ] Rust: Feature impl, one `#[path]` mount plus one registry entry, commands `async` + `blocking`, bindings regenerated, `ipc.ts` only, capability file.
- [ ] Containment: `guard` / `spawn` / `native`, no raw threads, `FeatureBoundary` for UI.
- [ ] Tests: register/unregister, kill switch, failing contribution, contract tests, Rust hooks and ACL.
- [ ] Spec, `CHANGELOG.md`, `TODOS.md`, `CLAUDE.md`, shortcuts doc updated.
- [ ] `vp check`, `vp test`, `cargo test`, `cargo fmt --check`, `cargo clippy` green.
- [ ] Report: name where DRY, SOLID and KISS conflicted and which won; what only a real window can verify.
