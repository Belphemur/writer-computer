# obsidian-host

TypeScript core of Writer's Obsidian-plugin host. Adapted from opensidian (GPL-3.0-or-later). Spec: `SPECs/obsidian-plugins-spec.md`. The app side lives in `src/stores/plugins-store.ts`, `src/components/plugins/`, `src/hooks/use-plugins.ts` and `workspace-bridge.ts` / `editor-bridge.ts` here.

## Architecture

```
PluginHost (loader.ts)            lifecycle, status map, script injection, require
  ├─ HostIpc (ipc.ts)             Rust backend boundary (faked in tests)
  ├─ App (api/app.ts)             what a plugin sees as `this.app`
  │    ├─ Vault + MetadataCache   over an injectable VaultIo (api/vault.ts, api/vault-io-tauri.ts)
  │    ├─ Workspace               over an injectable WorkspaceBridge (api/views.ts)
  │    └─ HostServices            commands / ribbon / status bar / setting tabs / registrations
  └─ obsidian-module.ts           the object `require("obsidian")` returns (ES5-subclassable classes)
```

- **Teardown has one write path.** Everything a plugin registers goes into an `OwnedRegistry` keyed by plugin id (`api/core.ts`); disabling is `plugin.unload()` (runs `register`/`registerEvent`/`registerInterval` cleanups, then `onunload`) followed by `services.sweep(id)` and removing the style tag. Workspace views and open modals are swept through `services.addSweeper`.
- **Loading.** `main.js` is injected as `<script src="writer-plugin://localhost/<id>/main.js?n=K">`. Rust serves it wrapped as `__writerPluginDefine("<id>", function (module, exports, require, process, global, Buffer) { ... })`. The global is installed non-writable by the loader; only a define for a pending load is honoured.
- **Status.** `host.getSnapshot()` / `host.subscribe` follow the `useSyncExternalStore` contract: `{trusted, booted, installed, status: {id: {state: "enabled" | "failed" | "disabled", error?}}}`. A failing plugin is torn down fully; its enabled flag stays set (Obsidian parity).
- **No in-page sandbox.** Tauri defines `__TAURI_INTERNALS__` non-writable and non-configurable, so the page cannot be sealed. A trusted vault's plugins run with the app's privileges (like Obsidian); Rust-side path authorization, native spawn consent and trusted-vault gating are the remaining defences. See the spec's Trust model.
- **App wiring.** `usePluginHostLifecycle` (mounted in `App`) attaches the store when a workspace window has resolved startup and detaches on workspace change; standalone/compact windows and the welcome screen never boot. `attach` reads backend state first and only boots when the vault is trusted (`plugins_state`); a boot failure is shown as `bootError` under Settings > Community plugins.
- **Host wiring points.** The host UI owns what is visible: it implements `WorkspaceBridge` (mount `leaf.containerEl`, reveal, active file/editor), renders `services.ribbon`/`statusBar` items (each has a ready DOM element), shows each `settingTabs` entry as a sidebar section of the Settings tab (`components/settings-panel/plugin-section.tsx`: attach `containerEl`, `display()`, `hide()` on teardown), wires `app.setting.openRequested` (`open()`, `openTabById(id)`) in `plugins-store`, calls `app.workspace.markLayoutReady()`, and forwards file-watcher events to `app.vault.notifyExternal`.

### Popups and boundaries

Popup placement is a host responsibility; plugins' popups are contained by the host. Three layers, one pure function (`src/lib/popup-position.ts`: `computePopupPosition` / `clampShift`):

- **Host-built popups** (`Menu`, `AbstractInputSuggest`, `EditorSuggest`, `PopoverSuggest`) mount in the body-level popup layer (`popup-layer.ts`, `#writer-popup-layer`: fixed, viewport-sized, click-through, z-index 10000, no transform/filter/contain so it never changes the fixed containing block or gets clipped by the side pane) and are kept visible by `trackPopup`: flip above/below by room (the side only changes when the current one stops fitting), clamp horizontally, cap `max-height` with an internal scroll, re-place on window resize, scroll (capture) and size changes.
- **Popups a plugin builds itself** (Copilot's @/[[/slash typeahead is `position: absolute; bottom: calc(100vh - top)` on a body child; its Radix menus/popovers/tooltips are body-level `position: fixed` wrappers): `popup-guard.ts` is installed with the first plugin (ref-counted like the DOM helpers) and removed with the last. It watches direct children of `<body>`; a floating one (fixed/absolute, or `role` listbox/menu/dialog/tooltip/combobox) that sticks out of the window is shifted back in through the independent CSS `translate` property (the plugin's own `top`/`bottom`/`transform` are never rewritten) and, if taller than the window, capped with an internal scroll. One that already fits is never touched; `data-writer-no-clamp` opts an element out. The guard only knows the popup's box, not its anchor, so it slides rather than flips; flipping is only done where the host knows the anchor. It re-checks on resize (a `ResizeObserver` on the root, because `resize` can fire before `innerHeight` settles in WebKit), scroll, popup size and `style` changes, batched in a 16 ms timer (not `requestAnimationFrame`: WebKit pauses it for a window that is not frontmost). Popups appended inside a plugin's own container (not under `<body>`) are not covered.
- Copilot's Radix `Portal container={activeDocument.body}` and `range.startContainer.win` rely on `activeDocument` and `Node.win`, which the DOM helpers provide.

`EditorSuggest` and `AbstractInputSuggest` are real classes now (placement + keyboard list), but nothing calls `EditorSuggest.onTrigger` yet: `registerEditorSuggest` still only records the suggest, so editor-triggered suggestions from plugins do not appear in Writer's editor.

E2E: `e2e/specs/copilot-popups.spec.js` (`SPEC=copilot-popups.spec.js sh fixtures/copilot-fake-claude/run.sh`) types `@`, `[[` and `/` in Copilot's chat input at the bottom of the side pane and opens its dropdowns in a small window, asserting every floating element lies inside `innerWidth` x `innerHeight`.

Stubbed or partial:

- **Networking (`api/network.ts`).** `requestUrl`/`request` run over `plugin_http_request` (CORS/CSP-free, binary-safe via base64). A plugin-scoped `fetch` runs over `plugin_http_stream_*` (always streamed, so SSE arrives incrementally; `response.body` is a page `ReadableStream`; AbortSignal calls `plugin_http_stream_cancel`; client-side queue of 16 slots with a 30s wait, then `TypeError`). Errors surface as `TypeError("Failed to fetch: ...")`. It is both the free variable `fetch` in the CJS wrapper and, while at least one plugin is loading/loaded, `globalThis.fetch`/`window.fetch` (idempotent, restored on last teardown; SDKs that capture the global are covered). Non-http(s), `ipc:`/`asset:`/`writer-plugin:`/`blob:`/`data:`, same-origin and `*.localhost` app hosts fall through to the page's fetch. Side effect: while patched, the app's own cross-origin http(s) fetches also go through Rust (trusted vault only). Headers/Request/Response/ReadableStream/etc. are the page's. Never logs bodies or auth headers.
- **Gaps:** `XMLHttpRequest`, `WebSocket`, `EventSource` are not provided (CSP still blocks them); `credentials`/`mode`/`cache` ignored; request body `ReadableStream`/Blob are buffered; forbidden request headers are dropped by the page's `Request`.
- `moment` is the real library (static import here; the whole host is a lazy chunk, so it stays out of the entry bundle).
- **Markdown rendering** (`api/markdown-render.ts`, installed by the PluginHost with `setMarkdownRenderer` while a plugin is loaded; the escaped-paragraph placeholder remains the fallback). `MarkdownRenderer.render` / `renderMarkdown` go through `marked` (context-free extensions) -> the shared DOMPurify core in `src/lib/safe-html.ts` (the plugin-browser README renderer uses the same core with its stricter config) -> a DOM post-pass that needs the vault. Output is Obsidian-shaped and `el` gets `.markdown-rendered`: `a.internal-link[data-href]` (`is-unresolved` via `metadataCache.getFirstLinkpathDest(path, sourcePath)`), `span.internal-embed` replaced by `img.image-embed` (Tauri asset URL of the vault file) or `div.markdown-embed` (note or `#heading` section, depth limit 3, cycle guard), `a.tag`, `div.callout[data-callout]` (title/content divs), `mark`, `%%comments%%` and frontmatter dropped, `$..$`/`$$..$$` as `span.math` text, task-list checkboxes (disabled), `pre > code.language-x` (no syntax highlighting: the app ships no highlighter outside the editor). Footnotes are not rendered. Clicks are delegated on `el` (one listener set per element however often it is re-rendered; removed when the passed `component` unloads): internal links and relative markdown links open in a new main tab (`openLinkText(..., true)`, a missing note raises a Notice), http(s)/mailto go to `openExternalUrl` (`node/external-links.ts`), tags and `#anchors` never navigate. Untrusted input: allowlisted tags/attributes, only allowlisted `class` values, no `id`/`style`/`on*`, hrefs http(s)/mailto/tel or vault-relative, images http(s), vault files or raster `data:image`. A newer render into the same `el` cancels pending embed reads of the older one. Styles: the `.markdown-rendered` block in `api/theme-compat.ts`. Tests: `tests/obsidian-host-markdown-render.test.ts`.
- Icons: registered SVGs render; other names render a neutral glyph (`data-icon`, `lucide-<name>` class). No icon pack is bundled.
- `registerEditorExtension` is live: the plugins store feeds the recorded extensions into the shared `pluginExtensionCompartment` (`editor-bridge.ts`, added by `createEditorExtensions`), reconfigured on enable/disable; a rejected extension resets the editors and shows an error. `editor.cm` is the active CodeMirror view.
- **Leaf placement.** `getRightLeaf`/`getLeftLeaf` leaves show in the right-hand plugin pane (no left sidebar). `getLeaf(true | "tab" | "split" | "window")` returns a main-area leaf: once a view is opened in it (`setViewState`) it becomes an editor tab (page kind `plugin-view`, transient, keep-alive, titled from `getDisplayText()`; `leaf.updateHeader()` re-titles it); closing the tab detaches the leaf and runs the view's `onClose`; `navigateToFile` never replaces such a tab. Writer has no splits or extra windows, so `"split"`/`"window"` are tabs. `getLeaf()`/`getLeaf(false)` is the editor leaf of the active note (a stable `WorkspaceLeaf` whose view is a `MarkdownView` with `file` and a live editor), also listed by `iterateAllLeaves`/`getLeavesOfType("markdown")`; `leaf.getRoot()` returns `leftSplit`/`rightSplit`/`rootSplit`.
- **Opening notes.** `openLinkText(link, source, newLeaf)` and `leaf.openFile(file)` open the note in the main editor through the editor-area open-file path: a truthy `newLeaf` (or any leaf other than the editor leaf) is a new tab, otherwise the current tab. `setViewState({type: "markdown", state: {file}})` does the same. A link to a missing note rejects (Obsidian would create it); `#heading`/line eState are not applied.
- **Active note events.** The plugins store subscribes once to the editor store and calls `workspace.syncActiveDocument()` (deduped, latest-wins, indexes a just-created note first): `file-open(file | null)` when the note changes, `active-leaf-change(leaf | null)` and `layout-change` when the note or the active plugin tab changes. Copilot reads the active note only after `active-leaf-change`. While a plugin tab is active `getActiveFile()` is null. A plugin enabled mid-session gets no replay; it reads `getActiveFile()`.
- **Home mounts (`node/home-mounts.ts`).** `fs` refuses paths outside the vault, but Copilot persists its chat index (the "Recent chats" list for Claude chats) in `~/.obsidian-copilot/vaults/<id>/agent-chat-index.json`. Mounted home folders (today `~/.obsidian-copilot`, Copilot's app-data directory) are served from `.obsidian/plugins/copilot/home/.obsidian-copilot` in the vault. The host's Copilot seed still sets `autosaveChat: false`, so markdown chat notes are only written when the user turns that on. Not covered: reading `~/.claude/projects/*.jsonl` transcripts to resume a native chat (outside the vault, EACCES).
- `registerMarkdownPostProcessor`, `registerMarkdownCodeBlockProcessor`, `registerExtensions`, `registerObsidianProtocolHandler`, `registerHoverLinkSource` only record into `services.registrations` (swept on disable); the host does not act on them yet. Side leaves open in the one right-hand plugin pane (no left sidebar); the pane is toggled from the command palette.
- No binary file IO (`readBinary` rejects); `fs` is a UTF-8 text subset (see Node surface).
- Intervals/timers a plugin creates with bare `setInterval` and listeners it adds to `window` itself are not tracked; use `registerInterval`/`registerDomEvent` (Obsidian's contract).
- Modals carry no owner, so disabling any plugin closes all open plugin modals.

## Node surface (`node/`)

Hand-written Node shims so bundled SDKs (the Claude Agent SDK, Copilot Agent Mode) run. `require(id)` (`modules.ts` -> `node/registry.ts`) resolves every id with or without `node:`; unknown ids throw `Error("Cannot find module 'x'")` with `code: "MODULE_NOT_FOUND"`. The factory receives `require`/`process`/`Buffer`; `PluginHost` also installs them (plus `SharedArrayBuffer` stand-in when missing, and `window.require`) as globals while a plugin is loading/loaded and restores them on the last teardown (`installNodeGlobals`; a real Node `process` is never replaced). The global `require` identifies the calling plugin from the stack (`writer-plugin://localhost/<id>/main.js` sourceURL).

- **Boot.** `preloadNodeRuntime` (awaited by the loader before any plugin script) fetches `plugin_os_info`, the login PATH (`plugin_resolve_login_path`, overrides `process.env.PATH`), `plugin_which("claude")`, and probes `[vault, ~/.claude, ~/.claude/settings.json, ~/.claude/local/claude, claude]` with `plugin_fs_probe`. It never rejects; failures fall back to defaults. Backend: injectable `NodeIpc` (`node/ipc.ts`, default Tauri; `PluginHostOptions.nodeIpc`).
- **Real:** `events` (class EventEmitter; `once/on/setMaxListeners` statics), `buffer` (Uint8Array subclass), `util`, `string_decoder`, `path` (posix + win32), `os`, `process` (shared object; no `versions.node`; `kill(pid)` via the pid table, negative = group; `on/once/emitWarning/exit` are inert and `process.on("exit")` NEVER fires), `stream` (Readable/Writable/Duplex/Transform/PassThrough/pipeline/finished/promises/toWeb/fromWeb), `readline`, `child_process` (spawn/execFile over `plugin_proc_*`), `crypto` (randomBytes/UUID/int, sync sha256+sha1, hmac), `url`, `fs`/`fs/promises`, `http`/`https` client over the global fetch, `electron.shell.openExternal` (http/https/mailto via the opener plugin), `module.createRequire` (returns the same `require`). Cheap shims in `node/extra-modules.ts`: `diagnostics_channel` (no subscribers ever), `perf_hooks`, `worker_threads` (main thread, `Worker` throws), `tty`, `v8` (inert), `vm` (throws: no eval under the CSP), `constants`, `querystring`, `punycode`, `domain`, `timers`, `timers/promises`, `sys`. Anything else (`tls`, `dns`, `http2`, `cluster`, ...) stays `Cannot find module`.
- **child_process.** `env` replaces the child env (`inherit_env: false`); no `env` sends `inherit_env: true`. `stdio` pipe|ignore|inherit(=ignore). `shell`, `exec`, sync variants and `fork` fail with clear errors. Spawn failures: `error` (ENOENT/EACCES, `errno`, `syscall`) then `close(-2)`, no `exit`; `close` waits for stdout/stderr to end; unread stdio is drained like Node's flushStdio.
- **fs.** Async: vault-confined UTF-8 text (readFile, writeFile, appendFile, stat, access, mkdir, rm, rmdir, unlink, rename, readdir, realpath, copyFile); outside the vault reads/writes are `EACCES`, `stat/access/realpath` use `plugin_fs_probe`. mkdtemp/open/streams/symlink/chmod: `ENOSYS`. Sync functions answer ONLY from the probe cache (`registerSyncProbePaths(paths)` is the host hook; `primeSyncFileContents(path, text)` makes `readFileSync` return content): unknown path = missing (`existsSync` false, others `ENOENT`), known file without primed content = `EACCES`, known dir lists `[]`. `fs.constants` exists.
- **Stubs:** `http.createServer().listen()` emits an async `EPERM` error and never listens; `net` (isIP\* only), `zlib` (all throw), `os.cpus()` is `[]`, `async_hooks.AsyncLocalStorage` has a synchronous context only (no propagation across `await`), `electron.ipcRenderer` (`sendSync` -> `undefined`, `invoke` rejects, others no-ops, `remote` undefined; `showItemInFolder` rejects).
- **Copilot helpers.** `node/device-id.ts` seeds `obsidian-copilot:device-id:v1` in localStorage only if absent. `node/seed-plugin-data.ts` writes Copilot's first-enable `data.json` (settingsVersion 16, Claude backend, `deviceProfiles[<device id>].claudeCliPath` from `plugin_which`) only for plugin id `copilot` and only if no data exists; the loader calls it before the plugin is constructed.

## Agent configuration (Copilot Agent Mode: Claude, Codex, OpenCode)

Copilot 4.0.20's agent backends are exactly **Claude** (CLI `claude`), **Codex** (adapter `codex-acp`, "Managed by Copilot" or "My own installation") and **OpenCode** (`opencode`, same two sources). Gemini and generic "custom agent" commands are not agents in 4.0.20 (custom connectors are MCP servers, a different feature). Everything below is host-side; Copilot is never modified.

- **Detection is synchronous in Copilot** (`existsSync` over candidate lists, `realpathSync`, `readFileSync` of package metadata) and WKWebView cannot block on IPC, so the host answers from a preloaded cache. `node/agent-clis.ts` is the single list (`AGENT_CLI_NAMES`, `agentBinDirs`, `versionRoots`): at boot every `<dir>/<cli>` candidate for the login PATH, Copilot's well-known dirs, `~/.local/bin`, `~/.opencode/bin`, `~/.codex-acp/bin`, `~/.bun`/`.npm-global`/`.volta`/`.asdf` bins and every nvm/fnm node version bin is probed, plus `plugin_which` of each CLI. A path that is NOT probed reads as missing (`existsSync` false), never as present: a stale "found" would be worse than "not detected".
- **`plugin_fs_probe` scope** (metadata only, never content except below): the vault; agent homes (`~/.claude`, `CLAUDE_CONFIG_DIR`, `~/.codex`, `~/.codex-acp`, `~/.opencode`, `~/.obsidian-copilot`, `~/.config/opencode`, `~/.local/share/opencode`); files DIRECTLY inside a PATH / well-known / node-tool bin dir; paths `plugin_which` returned for the window, their canonical target, and `provenance.json` / `package.json` next to that target or one directory up (content returned, 64 KiB cap; Codex validates its adapter with them). The listing of nvm/fnm version roots (names only) is returned so Copilot's `readdirSync` enumeration works. Everything else is a miss. Probe results carry `real` (canonical path: sync `realpathSync` of an npm `bin/codex-acp` symlink needs it), `entries` and `text`.
- **A path the user typed** (Claude/Codex/OpenCode "Apply" stats it through `fs.promises.stat/access`): outside the allow-list the shim confirms an absolute executable with `plugin_which(path)` (no process, no consent: an existing capability) and then probes it, so a custom install anywhere is accepted and its companions are primed. After a restart `configuredAgentPaths(data.json)` re-vouches for the absolute `*Path`/`*command` strings under `agentMode` before the plugin loads (`PluginHost.primeAgentPaths`).
- **Electron surface** (`node/misc.ts`, one implementation): `shell.openExternal` (http/https/mailto, Rust `plugin_open_url` re-validates), `shell.openPath` (resolves `""` or an error string, Electron's shape) and `shell.showItemInFolder` (never throws, failures are recorded) over Rust `plugin_open_path`, which only accepts existing entries inside the vault or an agent home and never anything launchable (`.app`, scripts, installers, executables). `electron.remote` is undefined, `ipcRenderer` is inert. There is no `dialog`: Copilot's agent settings have no Browse button, so no picker exists to drive.
- **External links** (`node/external-links.ts`, installed while a plugin is loaded): `window.open(url)` and un-handled clicks on `http(s)/mailto` anchors go to `openExternal` instead of being ignored or navigating the app window away. A click a plugin handled itself (`preventDefault`) wins.
- **`app.internalPlugins.getPluginById("file-explorer").instance.revealInFolder(folder)`** (Copilot's "Open Copilot folder") reveals the folder in the system file manager.
- **Modal layout.** The host owns `.modal-container` / `.modal-bg` / `.modal` / close button CSS (`api/theme-compat.ts`, from the public class names only). Without it a plugin's Configure/Install dialog is a static block appended after the app, off-screen: every "Configure" button looked dead.
- **Not supported: "Managed by Copilot" (Download & install) for Codex/OpenCode.** It streams a release to a folder outside the vault (`fs.createWriteStream`, `zlib`, `tar`), which Writer refuses; choose "My own installation" (install `codex-acp` / `opencode` yourself). Sign-in flows (`claude auth login`, `codex-acp cli login`) run through the normal spawn path and consent; the login URL is opened in the system browser from the link Copilot shows.
- **Seeding.** `seed-plugin-data.ts` still only writes on the FIRST enable; an existing data.json is never touched. A device id that matches no `deviceProfiles` entry is harmless now: Copilot falls back to its candidate list, which the preload makes truthful.

## Diagnostics and theme (found by the Copilot e2e)

- **`window.__writerPluginErrors`** (`error-log.ts`): ring buffer (100) of `{at, plugin, phase, message}` for plugin load, unload, seed and boot failures. Tests and a developer's console read it; it never leaves the page.
- **`app.secretStorage`** (`api/secret-storage.ts`): sync `getSecret/setSecret/deleteSecret/listSecrets` over an in-memory cache. `hydrate(ipc)` loads the OS credential store once (the loader calls it in `load(id)`, before any plugin script evaluates; writes made before it finishes are not clobbered) and every set/delete is written through on a serial chain. Backend failures (hydrate or write) go to `window.__writerPluginErrors` plus `console.warn`, the value stays in memory for the run. Rust side: `plugin_secrets.rs`, see the spec. Without the object Copilot raised an unhandled rejection at startup.
- **Obsidian CSS variables** (`api/theme-compat.ts`): public Obsidian variable names (`--size-4-4`, `--background-primary`, ...) mapped onto Writer's tokens, installed as one `<style data-writer-obsidian-theme>` while a plugin is loaded. Plugin stylesheets size icons and surfaces with them. Values are Writer's own.
- **Plugin CSS sanitizer** (Rust `plugins::sanitize_css`) works per statement (`;` `{` `}` newline), not per line: a minified single-line stylesheet used to be deleted whole by one `scroll-behavior:`.
- **`Element.onWindowMigrated(cb)`** exists (returns a disposer, never fires: single window).
- **Vault stat for hidden entries** (`vault-io-tauri.ts`): kinds of entries the directory listing hides come from `plugin_fs_probe`, not a guess (a guessed "file" for `copilot/skills` broke the vault index).
- **Device id** is seeded through `app.loadLocalStorage/saveLocalStorage` (vault-scoped, JSON), the same API Copilot reads, so `deviceProfiles[<id>]` matches.
- **Copilot e2e only**: the e2e-feature Rust build honours `WRITER_E2E_EXTRA_PATH` (prepended to the login PATH `plugin_which` sees). Not compiled into release builds.

## Bases views

`Plugin.registerBasesView(viewId, {name, icon, factory, options})` (`api/bases-view.ts`, called through `App.registerBasesView`) registers the type in the one Bases view registry (`src/lib/bases/view-registry.ts`) that the built-in table, cards and list also use, with the plugin id as owner. It returns `true`, or `false` when the id is taken (built-in or another plugin, first registration wins); a registration without a name and factory throws a `TypeError`. `PluginHost.teardown` removes the plugin's view types through `services.sweep(id)` (`unregisterBaseViewsOwnedBy`), the open tab then shows the placeholder and the view instance is unloaded.

- **Lifecycle.** The tab mounts the view into a container (`components/base-view/plugin-view-host.tsx`); `PluginViewInstance` calls `factory(controller, container)` (the controller is an opaque `QueryController`), `load()`s the `BasesView`, and then calls `onDataUpdated()` once per animation frame after every data, view or document change (several updates in one frame become one call), with a fresh `BasesQueryResult` assigned to `this.data` each time: `data`, `groupedData` (`BasesEntryGroup`, `key` as a `Value`, one keyless group when ungrouped), `properties`, `getSummaryValue` (only for the whole result or a whole group, and only for summaries configured on the view; anything else is an `ErrorValue`). `BasesEntry.file` is the vault `TFile` (a stand-in when the vault cache does not know the path yet); `getValue(id)` returns the `Value` of a queried property or `null`. `destroy()` cancels the pending frame and `unload()`s the view. A throwing factory or `onDataUpdated` shows a red message in the container and is recorded in `window.__writerPluginErrors` (`bases-view:*`).
- **Values.** `api/bases-values.ts` implements the public `Value` shapes (`NullValue`, `BooleanValue`, `NumberValue`, `StringValue`, `DateValue`, `ListValue`, `ObjectValue`, `LinkValue`, `UrlValue`, `FileValue`, `HTMLValue`, `ImageValue`, `IconValue`, `RegExpValue`, `ErrorValue`, `DurationValue`) from the engine's tagged values; `toString()` is the engine's display text and `renderTo` writes text only (never HTML).
- **Config.** `config.get(key)` reads the view's YAML (unknown keys first, then the typed ones); `getAsPropertyId`, `getOrder`, `getSort`, `getDisplayName` read the live view; `config.set(key, value)` goes through the same write path as the toolbar (`ViewConfig.setOption`, one `.base` edit, comments and other keys kept; `null` removes the key) and throws for the keys the view model owns (`type`, `name`, `filters`, `groupBy`, `groupOrder`, `sort`, `order`, `limit`, `columnSize`, `summaries`).
- **Options.** `options(config)` descriptors (`dropdown`, `file`, `folder`, `formula`, `multitext`, `property`, `slider`, `text`, `toggle`, `group`) are adapted by `adaptOptions` and rendered in the toolbar's Settings popover (`components/base-view/view-settings.tsx`); values persist under `key`. A `property` option makes the host query that property even when the view does not show it (the entry is then in `data` but not in `data.properties`). A malformed `options()` is logged and shows no controls.
- **Formulas.** `getEvaluatedFormula(view, key)` is synchronous in the API but evaluation is a backend call, so the host evaluates every declared `formula` option (`base_eval`, `this` = the base file, the base's own formulas resolvable) before each `onDataUpdated`; the call returns that cached `Value`, `NullValue` for an unset option and an `ErrorValue` for a failing expression or a key that `options()` does not declare. Not implemented: `hover link`, `openLinkText` from the view (use `app.workspace`), `createFileForView` is a simple "new note next to the base, apply frontmatter, open it".
- **Unverified.** Only a fake plugin written after the public guide is tested (`tests/obsidian-host-bases-view.test.tsx`); no real community Bases plugin has been run, and the `obsidian.d.ts` Value classes are implemented from the public shapes, not diffed against it.

## Compat notes: load-time surface audits (Dataview, Tasks, Slides Extended, Templater)

Audited from the public sources of each plugin (read-only clones, deleted afterwards) and the public `obsidian.d.ts` (obsidianmd/obsidian-api). Never run against a real window yet: everything below is unit-tested only, real-window verification is still needed.

- **Complete named-export list.** `createObsidianModule()` now exports every value of the public `obsidian.d.ts` (classes, functions, constants). `api/compat-exports.ts` holds the long tail: real constructible bases (`SettingPage`, `SettingGroup`, `ConfirmationModal`/`ConfirmationButton`, `HoverPopover`, `Workspace*` tree classes, `MarkdownPreviewRenderer`, `ProgressBarComponent`, `Tag/RelativeDate/NotNullValue`, ...) and functions (`getLanguage`, `setTooltip`/`displayTooltip`, `getFrontMatterInfo`, `resolveSubpath`, `stripHeading*`, `iterateRefs`, `parsePropertyId`, base64/hex helpers, `htmlToMarkdown`, `renderMath`, ...). `tests/obsidian-host-module-exports.test.ts` pins the list (and that each class can be `extends`ed, ES6 and ES5 style): a missing export fails a test, not a user. Update the list when the typings change. Cheap stubs, honest limits: `htmlToMarkdown` returns text only, `renderMath` shows the source, `loadMathJax/Mermaid/PdfJs/Prism` resolve with nothing, tooltips are `title` attributes, `HoverPopover`/`MarkdownPreviewView` are inert, the `Workspace*` classes keep no layout tree.
- **`getLanguage()`** returns the webview locale lower-cased with the region kept (`en`, `pt-br`); fixes Tasks ("`getLanguage` is not a function").
- **`Workspace.updateOptions()`** (Dataview, Tasks, Templater call it) re-dispatches the registered plugin extensions to every live editor through `WorkspaceBridge.reapplyEditorOptions`.
- **`editorInfoField`, `editorLivePreviewField`, `editorEditorField`, `editorViewField`, `livePreviewState`**: real CodeMirror fields every Writer editor carries (`editor-bridge.ts`, in the plugin compartment so they exist in every state). `editorInfoField` yields `{app, file, editor}` resolved lazily through the host (empty after shutdown); live preview is always `true`. - **Added members** (public typings): `Workspace.getUnpinnedLeaf/getLeafById/getGroupLeaves/iterateRootLeaves/getLayout/requestSaveLayout/changeLayout/splitActiveLeaf/createLeafBySplit/createLeafInParent/duplicateLeaf/openPopoutLeaf/moveLeafToPopout/ensureSideLeaf/leftRibbon/rightRibbon`; `Vault.createBinary/modifyBinary/appendBinary/recurseChildren`; `FileManager.generateMarkdownLink/getAvailablePathForAttachment/promptForDeletion`; `app.internalPlugins.getEnabledPluginById` (always null, there are no core plugins). `.workspace-leaf-content` carries `data-type=<view type>` like Obsidian (plugin CSS keys on it).
- **V8 stack API** (`node/v8-stack.ts`, installed by `preloadNodeRuntime`): the macOS webview is JavaScriptCore, which ignores `Error.prepareStackTrace`. Bundled Node code (Slides Extended -> fastify -> `depd`) calls `callSite.getFileName()` on what it gets from `captureStackTrace` and crashed with "getFileName is not a function". On non-V8 engines `Error.captureStackTrace` is wrapped so a custom `prepareStackTrace` receives CallSite-like objects parsed from the string stack (file, line, column, function, type, method, isNative, ...). No-op on V8. Only `captureStackTrace` is wrapped, not reads of `new Error().stack`.
- **Missing-API diagnostic** (`missing-api-log.ts`): the `app` a plugin receives (and `workspace`, `vault`, `vault.adapter`, `metadataCache`, `fileManager`) is wrapped in a Proxy that logs once per plugin and path (`[plugin-api] "dataview" used unimplemented app.workspace.foo`) and still returns `undefined`. ## Plugin pane layout, selection and markdown

- **Structure.** `.workspace-leaf` > `.workspace-leaf-content[data-type]` > `.view-header` + `.view-content` (`containerEl.children[1]`). The pane mounts the leaf in `[data-plugin-leaf-host]` (flex column, `overflow-hidden`, definite height from the pane); `api/theme-compat.ts` makes leaf and leaf-content flex columns with `min-height: 0` and `.view-content` `flex: 1 1 auto; min-height: 0; overflow: auto` (zero-specificity `:where()`, so plugin CSS wins; plugins that pin an input at the bottom set their own overflow). Deviation from a strict `overflow: hidden`: a generic list view that relies on `.view-content` scrolling keeps working. Needs verification in a real window (Copilot's bottom-pinned input).
- **Window chrome overlay.** The window drag region (z-30, 72px) and the editor tab bar (z-40) overlay the top of the right pane. The pane header sits at z-50 with `pointer-events: none` and only its controls `pointer-events: auto`; before that, the close button and plugin tabs were covered and clicks did nothing.
- **Text selection.** `App.css` disables selection globally; plugin-hosted content (`[data-plugin-leaf-host]`, `.modal-container`, `.is-selectable`, `.markdown-rendered`) is excluded from that rule and set to `user-select: text`, with buttons, icons and view headers inside it staying non-selectable. The native Copy menu item is registered in Tauri and no keyboard handler intercepts Cmd+C; real-window copy still to be confirmed.
- **Markdown paragraphs.** Plugin-rendered markdown (`api/markdown-render.ts`) uses `marked` with `breaks: true` (Obsidian's default, "Strict line breaks" off: a single newline is a visible break) and `.markdown-rendered` restores paragraph/list/heading/hr spacing zeroed by Tailwind preflight (`p { margin: 0 }`, `ul { list-style: none }`) from `--p-spacing`. This was a plugin-pane rendering problem, not the note editor.
